# Greenhouse Temperature and Relative Humidity Forecasting

[![DOI](https://zenodo.org/badge/1353825395.svg)](https://doi.org/10.5281/zenodo.22648215)

Data, reproducible Jupyter notebooks, article figures, and documentation supporting multi-resolution and multi-horizon forecasting of greenhouse air temperature and relative humidity.

> **Repository status:** Version `v1.0.0` has been released and archived in Zenodo. The complete computational workflow has been executed sequentially from the raw dataset.

## Overview

This repository contains the reproducible research materials associated with a greenhouse environmental time-series forecasting study. The workflow covers sensor evaluation, temporal quality control, multi-resolution dataset construction, model-family benchmarking, robust residual hybrid modeling, and paired statistical analysis.

The study includes:

- evaluation of SHT31 and BME280 measurements;
- quality control and regularization to a uniform 4-minute grid;
- construction of 4, 12, 20, 30, and 60 min time series;
- forecasting at 60, 120, 240, and 480 min horizons;
- baseline, statistical, machine-learning, deep-learning, advanced traditional, and robust hybrid model families;
- chronological train-validation-test evaluation;
- Friedman, Wilcoxon-Holm, paired bootstrap, and Diebold-Mariano analyses;
- generation of article-ready figures.

## Study Design

The forecasting targets are:

- greenhouse air temperature;
- greenhouse relative humidity.

Five temporal resolutions and four forecast horizons are evaluated:

- temporal resolutions: 4, 12, 20, 30, and 60 min;
- forecast horizons: 60, 120, 240, and 480 min.

The combination of five resolutions, four horizons, and two targets produces 40 forecasting tasks per model family.

Chronological partitions are used throughout the workflow:

- training: March 22 to July 4, 2026;
- validation: July 5 to July 26, 2026;
- test: July 27 to August 19, 2026.

## Installation

The final workflow was executed with Python 3.13.9. Create an isolated environment and install the exact package versions listed in `requirements.txt`.

Using Conda:

```bash
git clone https://github.com/JorgeMogollon/greenhouse-temperature-humidity-forecasting.git
cd greenhouse-temperature-humidity-forecasting

conda create --name greenhouse-forecasting python=3.13.9
conda activate greenhouse-forecasting

python -m pip install --upgrade pip
python -m pip install -r requirements.txt

jupyter lab
```

A GPU is optional. TensorFlow can run on CPU, although the deep-learning notebook may require substantially more execution time.

## Reproducing the Workflow

The only required input file is:

```text
data/raw/greenhouse_sensor_data_raw.csv
```

Execute notebooks `01` through `10` in numerical order from the repository root. The workflow regenerates intermediate and final computational outputs locally, including:

- `data/processed/`;
- `results/`;
- `models/`;
- `preprocessors/`;
- `metadata/`.

These directories are excluded from version control because they are reproducible products of the workflow.

## Reproducibility Principles

- All model families use common forecast origins within each temporal resolution.
- Training, validation, and test partitions are chronological.
- Model selection and hyperparameter decisions use only training and validation data.
- Test data are reserved for final out-of-sample evaluation.
- Deep-learning candidates are evaluated across independent random seeds.
- The robust hybrid correction is activated only when predefined validation criteria are satisfied; otherwise, the selected advanced traditional model is retained through `BASE_ONLY`.
- Final statistical comparisons are performed across the same 40 forecasting tasks.
