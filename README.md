greenhouse-temperature-humidity-forecasting
Data, reproducible notebooks, figures, results, and metadata supporting the
analysis and forecasting of greenhouse air temperature and relative humidity
at multiple temporal resolutions and forecasting horizons.
> **Repository status:** active development. The first archived Zenodo release
> and DOI will be added once the reproducible workflow is complete and the
> repository is made public.
Overview
This repository provides the reproducible research materials associated with a
greenhouse environmental time-series forecasting study. The current workflow
includes sensor evaluation, validation of the original observations, temporal
quality control, and regularization to a uniform 4-minute time grid.
Additional forecasting stages will be incorporated progressively as they are
completed and validated.

Data
Raw data
`data/raw/greenhouse_sensor_data_raw.csv`
Original sensor observations preserved as the source dataset for the
reproducible workflow. The raw file is intentionally retained without
silently modifying the source column names or observations.
Validated data
`data/processed/greenhouse_sensor_data_validated.csv`
Validated observations generated by `01_sensor_evaluation.ipynb`. This stage
standardizes the sensor-to-variable mapping and records the quality assessment
used by subsequent analyses.
4-minute regularized data
`data/processed/greenhouse_sensor_data_4min.csv`
Quality-controlled dataset mapped to a uniform 4-minute temporal grid by
`02_quality_control_regularization.ipynb`. The file includes cleaned variables,
observation/interpolation flags, and quality-status information.
Reproducible workflow
01 — Sensor evaluation
`notebooks/01_sensor_evaluation.ipynb`
Main tasks:
audits the original greenhouse sensor records;
verifies sensor-to-column mapping;
evaluates agreement between SHT31 and BME280 measurements;
identifies BME280 relative-humidity saturation behavior;
generates the validated dataset;
exports diagnostic tables and figures.
02 — Quality control and temporal regularization
`notebooks/02_quality_control_regularization.ipynb`
Main tasks:
audits timestamps and duplicate records;
maps observations to a uniform 4-minute grid;
performs physical-range quality checks;
interpolates only eligible short internal gaps;
preserves quality and provenance flags;
generates the 4-minute processed dataset;
exports quality-control tables, figures, and analysis metadata.
The current configuration is stored in:
`metadata/02_analysis_configuration.json`

Results
Tabular audit and quality-control outputs are stored in:
```text
results/
├── sensor_evaluation/
└── quality_control/
```
These files provide machine-readable summaries of the decisions and checks
performed during preprocessing.
Reproducibility
The notebooks are designed to locate the repository root dynamically and use
repository-relative paths rather than requiring a fixed local directory.
The intended execution order is:
```text
01_sensor_evaluation.ipynb
        ↓
greenhouse_sensor_data_validated.csv
        ↓
02_quality_control_regularization.ipynb
        ↓
greenhouse_sensor_data_4min.csv
        ↓
subsequent forecasting notebooks
```
A complete environment specification and dependency file will be added before
the first archived release.
